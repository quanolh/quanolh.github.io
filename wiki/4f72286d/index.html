PMP核心知识体系

PMP 核心知识体系

一、PMP 是什么

PMP（Project Management Professional）是项目管理专业人士资格认证，
由美国项目管理协会（PMI）发起，是目前全球公认最具权威的项目管理认证。

核心依据：PMBOK 指南

PMBOK（Project Management Body of Knowledge）是 PMP 考试的官方教材，
第7版起采用十二原则 + 八大绩效域的新框架，但第6版的五大过程组 + 十大知识领域仍是核心知识体系。

二、三大核心框架

2.1 五大过程组

项目管理的生命周期，按时间顺序：

过程组 核心任务 关键产出
启动 定义项目，获得授权 项目章程、相关方登记册
规划 制定目标，明确行动方案 项目管理计划、基准
执行 整合资源，完成项目工作 可交付成果、工作绩效数据
监控 跟踪进度，控制变更 工作绩效信息、变更请求
收尾 正式结束项目或阶段 最终产品、经验教训 
过程组关系（非严格顺序）

        ┌─────────┐
        │  启动   │
        └────┬────┘
             ↓
        ┌─────────┐
        │  规划   │←─────────────┐
        └────┬────┘              │
             ↓                   │
   ┌─────────────────┐           │
   │  执行 ←───→ 监控 │───────────┘
   └─────────────────┘    (迭代调整)
             ↓
        ┌─────────┐
        │  收尾   │
        └─────────┘

2.2 十大知识领域

项目管理的专业领域，按管理内容划分：

知识领域 管理对象 核心问题
整合管理 项目整体 如何统筹协调？
范围管理 做什么 项目边界在哪里？
进度管理 何时做 需要多长时间？
成本管理 花多少钱 预算是多少？
质量管理 做得怎样 满足要求了吗？
资源管理 谁来做 需要哪些资源？
沟通管理 信息传递 如何保持信息同步？
风险管理 不确定性 可能发生什么问题？
采购管理 外部资源 需要外包什么？
相关方管理 利益相关者 谁影响项目？

2.3 四十九个过程

每个过程属于一个过程组和一个知识领域：

过程分布（按过程组）

启动（2个）
├── 制定项目章程
└── 识别相关方

规划（24个）
├── 制定项目管理计划
├── 规划范围/进度/成本/质量/资源/沟通/风险/采购/相关方管理
├── 定义范围/活动/估算...
└── ...

执行（10个）
├── 指导与管理项目工作
├── 管理质量/资源/沟通/风险/采购/相关方参与
└── ...

监控（12个）
├── 监控项目工作
├── 实施整体变更控制
├── 确认范围/控制范围/进度/成本/质量/资源/采购...
└── ...

收尾（1个）
└── 结束项目或阶段

三、核心概念详解

3.1 项目与运营

维度 项目 运营
特性 临时性、独特性 持续性、重复性
目的 创造独特产品/服务/成果 维持业务运转
结束条件 目标达成或项目终止 组织停止运营
示例 开发新产品、建设桥梁 生产流水线、客服中心

3.2 项目生命周期

项目生命周期

开始 ──────────────────────────────────────► 结束
  │                                           │
  ├── 预测型（瀑布）                           │
  │   需求明确，阶段顺序执行                    │
  │   ┌───┬───┬───┬───┬───┐                  │
  │   │需求│设计│开发│测试│上线│               │
  │   └───┴───┴───┴───┴───┘                  │
  │                                           │
  ├── 适应型（敏捷）                           │
  │   需求变化，迭代增量交付                    │
  │   ┌───┐┌───┐┌───┐┌───┐                   │
  │   │迭代1││迭代2││迭代3││迭代4│              │

  │                                           │
  └── 混合型                                   │
      预测型 + 适应型结合                       │

3.3 三重约束（铁三角）

约束 说明 相互影响
范围 项目要完成的工作总量 范围↑ → 时间↑ 成本↑
时间↓ → 范围↓ 或 成本↑
成本↓ → 范围↓ 或 时间↑
时间 项目完成所需时长
成本 项目所需的资源投入

第四约束：质量——受三重约束影响

四、十大知识领域详解

4.1 整合管理

核心作用：项目的大脑，统筹全局

整合管理（7个过程）

启动：制定项目章程 ──────► 正式授权项目经理
  │
规划：制定项目管理计划 ──► 整合所有子计划
  │
执行：指导与管理项目工作 ─► 执行计划，产出成果
  │     管理项目知识 ──────► 利用和创造知识
  │
监控：监控项目工作 ──────► 跟踪进度绩效
  │     实施整体变更控制 ──► 审批变更请求
  │
收尾：结束项目或阶段 ────► 正式关闭项目

关键文档：

文档 作用 创建时机
项目章程 正式授权项目 启动阶段
项目管理计划 指导项目执行 规划阶段
变更日志 记录变更历史 全过程

4.2 范围管理

核心作用：明确做什么、不做什么

范围管理（6个过程）

规划范围管理 ─────► 如何定义和控制范围
      │
收集需求 ─────────► 相关方需要什么
      │
定义范围 ─────────► 明确项目边界
      │
创建 WBS ─────────► 分解工作（核心工具）
      │
确认范围 ─────────► 正式验收可交付成果
      │
控制范围 ─────────► 管理范围变更

WBS（工作分解结构）：

项目名称
├── 1. 需求分析
│   ├── 1.1 用户调研
│   ├── 1.2 需求文档
│   └── 1.3 需求评审
├── 2. 系统设计
│   ├── 2.1 架构设计
│   └── 2.2 详细设计
├── 3. 开发实现
│   ├── 3.1 前端开发
│   └── 3.2 后端开发
└── 4. 测试部署
    ├── 4.1 单元测试
    └── 4.2 系统测试

4.3 进度管理

核心作用：确保项目按时完成

进度管理（7个过程）

规划进度管理 ─────► 如何管理进度
      │
定义活动 ─────────► 识别具体活动
      │
排列活动顺序 ─────► 确定依赖关系
      │
估算活动持续时间 ─► 每个活动需要多久
      │
制定进度计划 ─────► 创建进度模型
      │
控制进度 ─────────► 监控进度状态

关键工具：

工具 用途
甘特图 可视化展示进度
关键路径法（CPM） 找出最长路径，决定最短工期
挣值分析（EVA） 综合评估进度和成本绩效

4.4 成本管理

核心作用：确保项目在批准预算内完成

过程 核心任务 关键产出
规划成本管理 制定成本管理计划 成本管理计划
估算成本 估算完成项目所需资源成本 成本估算、估算依据
制定预算 汇总估算，建立成本基准 成本基准、项目资金需求
控制成本 监督状态，管理变更 工作绩效信息、成本预测

4.5 质量管理

核心作用：确保项目满足需求

质量管理（3个过程）

规划质量管理 ─────► 确定质量标准和要求
      │
管理质量 ─────────► 执行质量活动，过程改进
      │                （过程层面）
控制质量 ─────────► 检查可交付成果是否符合标准
                   （结果层面）

核心理念：
├── 预防胜于检查
├── 质量是规划出来的，不是检查出来的
└── 持续改进（PDCA循环）

4.6 资源管理

核心作用：确保项目有合适的人力和物力

资源类型 管理重点 关键工具
团队资源 组建、建设、管理团队 责任分配矩阵（RACI）
实物资源 设备、材料、设施管理 资源分解结构

RACI 矩阵：

活动 张三 李四 王五
需求分析 R（执行） A（负责） C（咨询）
系统设计 C R A
代码开发 I（知情） R R

4.7 沟通管理

核心作用：确保信息及时、准确传递

沟通模型

发送方 ──[编码]──► 信息 ──[媒介]──► 接收方
                                            │
                                     [解码/理解]
                                            │
                     反馈 ◄─────────────────┘

沟通管理（3个过程）
├── 规划沟通管理：制定沟通策略
├── 管理沟通：执行沟通计划
└── 监督沟通：确保沟通有效

沟通渠道数 = n×(n-1)/2（n为相关方数量）

4.8 风险管理

核心作用：识别和管理不确定性

风险管理（7个过程）

规划风险管理 ─────► 如何开展风险管理
      │
识别风险 ─────────► 找出潜在风险
      │
实施定性风险分析 ─► 评估优先级（概率×影响矩阵）
      │
实施定量风险分析 ─► 量化风险影响（蒙特卡洛模拟等）
      │
规划风险应对 ─────► 制定应对策略
      │
实施风险应对 ─────► 执行应对计划
      │
监督风险 ─────────► 跟踪和控制风险

风险应对策略：

类型 策略 说明
威胁 规避 消除威胁
威胁 转移 转给第三方（如保险）
威胁 减轻 降低概率或影响
威胁 接受 主动接受或被动接受
机会 开拓 确保机会发生
机会 分享 与他方合作
机会 提高 提高概率或影响
机会 接受 愿意利用机会

4.9 采购管理

核心作用：从外部获取产品或服务

过程 核心任务
规划采购管理 决定采购什么、如何采购
实施采购 获取卖方应答、选择卖方
控制采购 管理采购关系、监督合同绩效

      │
管理相关方参与 ──► 沟通和协作，满足需求
      │
监督相关方参与 ──► 监督关系，调整策略

五、关键工具与技术

5.1 挣值分析（EVA）

综合评估项目绩效的核心工具：

指标 公式 含义
PV 计划价值 计划完成工作的预算成本
EV 挣值 实际完成工作的预算成本
AC 实际成本 实际完成工作的实际成本
CV EV - AC 成本偏差（正=节约）
SV EV - PV 进度偏差（正=提前）
CPI EV / AC 成本绩效指数（>1=节约）
SPI EV / PV 进度绩效指数（>1=提前）

5.2 关键路径法（CPM）

关键路径 = 项目中最长的路径 = 项目最短工期

示例：
     A(3天)     B(2天)
开始 ─────► ─────► ─────► 结束
     │               │
     └── C(4天) ─────┘

关键路径：A → C = 3+4 = 7天
（非 A → B = 3+2 = 5天）

关键路径上的活动 = 关键活动
关键活动延误 = 项目延误

六、PMP 考试要点

考试结构

项目 内容
题目数量 180 题（170单选 + 10多选）
考试时间 230 分钟
题目类型 单选题 + 多选题
通过标准 约 60% 正确率

题目分布

题型分类与占比

分类 占比 介绍
情景题 约50% 核心难点，真实项目场景，考决策与应用
概念题 10%-20% 基础定义、术语、流程
计算题 10% 挣值EVM、关键路径CPM、沟通渠道等
敏捷/混合题 50% Scrum、Kanban、迭代管理

三大领域占比（第七版）

领域 占比 题目数 内容
人员（People） 42% 约 76 题 领导力、团队、干系人
过程（Process） 50% 约 90 题 五大过程、预测/敏捷/混合
商业环境（Business Env） 8% 约 14 题 战略、治理、合规

核心思维

PMP 核心思维

1. 以相关方为中心
   └── 识别、分析、管理相关方

2. 以价值为导向
   └── 交付业务价值，非仅完成工作

3. 过程思维
   └── 按过程组逻辑处理问题

4. 整合思维
   └── 全局视角，协调各方
